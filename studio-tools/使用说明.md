基于 FreeRDP **3.33.1**（Windows 客户端 `wfreerdp`）定制，对标 mstsc 的操作手感，
额外提供**后台文本注入**与**后台截图**，用于自动化。

- 桌面图标：`FreeRDP.lnk` → `wfreerdp.exe`
- 源码：同仓库 `upstream\`，分支 `studio-rdp-client`
- 版本：`9f08c28`（含后台截图）

| 文件 | 作用 |

## 2. 启动

### 图形方式

双击桌面 `FreeRDP`，在对话框里填地址/端口/用户/密码，勾选「保存密码」后连接。

- 凭据存入 Windows 凭据管理器，键名 `TERMSRV/<host>` 或 `TERMSRV/<host>:<port>`，下次自动回填。
- 证书使用 `/cert:ignore` 直连（内网自签场景），不再弹证书确认框。
- 记住上次连接的地址与密码，也记住上次选中的显示器。

### 命令行方式

```powershell
.\wfreerdp.exe /v:192.168.98.184 /u:DOMAIN\user /f /cert:ignore /kbd:unicode:on
```

对话框启动时会自动补上这些默认参数，等价于：

```
/f                     全屏
+toggle-fullscreen     允许退出全屏（浮条上的最小化/还原按钮依赖它）
+dynamic-resolution    窗口尺寸变化同步给远端
+auto-reconnect        断线自动重连
/gdi:sw                软件 GDI（文字更锐利，兼容性更好）
/bpp:32                32 位色
/kbd:unicode:on        Unicode 键盘（粘贴文本依赖它）
/cert:ignore           忽略证书
/log-level:WARN        日志级别
```

## 3. 全屏与多显示器

- 会话锁定到**启动时鼠标所在的那块显示器**，分辨率取该屏物理分辨率。
- 会话缩放（DPI）取该屏缩放比例：主屏 3840×2160@225%，副屏 2560×1440@150%。
- 显示器选择按**序号**持久化（`%LOCALAPPDATA%\FreeRDP\studio-monitor.txt`）。

### 画面模糊排查

按顺序排除：

1. **远端分辨率低于本机窗口** —— 最常见。远端墙纸/图标被放大即为此症状。
   解决：远端「显示设置」里把分辨率调到与客户端窗口一致；或让 RDP 以目标分辨率重开会话。
2. **远端会话 DPI 是 100%，而本机是 225%** —— 客户端会在连接时把本机缩放写进 `CS_CORE`，
   但**无法在会话中途修改已有会话的 DPI**（mstsc 同样不能）。需要注销一次远端会话或重启远端机器后重连。
3. **窗口模式下的 SmartSizing** —— 窗口模式是等比缩放（会有轻微模糊），全屏是 1:1。要看清晰文字请用全屏。

## 4. 顶部连接条（浮条）

全屏时顶部居中显示，鼠标靠近顶端出现；可在按钮以外的空白区域操作：

| 操作 | 行为 |
|---|---|
| 左右拖动条身 | 控制条在屏内左右移动 |
| 向下拖过约 2 个条高 | **退出全屏**，窗口随鼠标移动，松手落位 |
| 双击条身 | 切换全屏 |
| 图钉 | 固定 / 自动隐藏 |
| 最小化 | 最小化窗口 |
| 还原 | 切换全屏 |
| 关闭 | 断开连接 |

尺寸跟随所在屏幕的缩放（150% 屏 864×40，225% 屏 1296×60）。

## 5. 粘贴文本（Ctrl+V）

在客户端窗口里按 `Ctrl+V`，客户端把**本机剪贴板文本**通过 RDP 键盘通道逐字输入到远端。

- **不需要远端支持剪贴板重定向**（内网策略常禁用），因此远端无法粘贴回本机属于正常现象。
- 使用 **Unicode 键盘事件**，不受远端输入法/键盘布局影响。
- `CRLF` 只产生一次换行（不会行数翻倍）。
- 粘贴中按 `Esc` 立即中止；重复按 `Ctrl+V` 会被忽略。
- **客户端失焦/最小化时会继续粘贴**（每批发送前清除 `SuspendInput`）。

### 速率与完整性（实测，同一台远端、同一段 7600 字符）

| 节奏 | 实测速率 | 结果 |
|---|---|---|
| 1 字 / 5 ms | 179 cps | 完整 |
| **1 字 / 1 ms（默认）** | **632 cps** | **完整** |
| 1 字 / 0.5 ms | 1257 cps | 丢字 |
| 10 字 / 5 ms | 1769 cps | 丢字、串序 |

11,400 字符在默认速率下验证完整（300 行文本，行数、内容一致）。

### 调参（不改代码）

```powershell
$env:STUDIO_PASTE_PER_TICK = "5"    # 每批字符数，默认 1
$env:STUDIO_PASTE_TICK_MS  = "5"    # 每批间隔毫秒，默认 1
```

> 速率再往上会被远端输入队列丢弃（客户端侧零拒绝，丢在服务端），所以默认取 632 cps。

## 6. 后台注入（`SendRdpInput.exe`）

通过 `WM_COPYDATA` 直接把输入投给客户端进程，**不需要远端窗口在前台**，客户端最小化也有效。

窗口标题（仅主机名/IP）是匹配依据，因此**同一主机不要同时开多个客户端实例**。

```powershell
# 连接状态：Connected / Unicode / InputSuspended / TargetInBackground
.\SendRdpInput.exe --target 192.168.98.184:3389 --status query

# 输入文本（Unicode，逐字）
.\SendRdpInput.exe --target 192.168.98.184:3389 --text "hello 世界"

# 组合键：CTRL+A、SHIFT+TAB、WIN+R、F5、方向键、ENTER、ESC、BACKSPACE …
.\SendRdpInput.exe --target 192.168.98.184:3389 --key CTRL+A

# 滚轮：正数向上，负数向下
.\SendRdpInput.exe --target 192.168.98.184:3389 --wheel -3

# 空闲保活计数（查询已发送次数）
.\SendRdpInput.exe --target 192.168.98.184:3389 --keepalive 1

# 后台截图（见下一节）
.\SendRdpInput.exe --target 192.168.98.184:3389 --capture C:\rdpcap\shot.bmp

# 鼠标移动 / 单击 / 右键 / 按下 / 抬起（坐标是远端会话像素，左上角为原点）
.\SendRdpInput.exe --target 192.168.98.184:3389 --move 1920,1000
.\SendRdpInput.exe --target 192.168.98.184:3389 --click 40,2080       # 点开始按钮
.\SendRdpInput.exe --target 192.168.98.184:3389 --rclick 1800,300
.\SendRdpInput.exe --target 192.168.98.184:3389 --down 300,300        # 拖拽起手
.\SendRdpInput.exe --target 192.168.98.184:3389 --move 800,700
.\SendRdpInput.exe --target 192.168.98.184:3389 --up 800,700          # 拖拽收尾
```

`--click` 等价于「移动 + 左键按下 + 左键抬起」，一次调用完成；`--rclick` 为右键。
拖拽用 `--down` → `--move` → `--up` 三步。坐标取远端会话分辨率（例如 3840×2160 时任务栏在 y≈2080）。

返回码：`0` 成功并已投递；非 0 表示被拒绝（客户端会打印 `Client rejected input`）。

注入前客户端会临时清除 `SuspendInput`，发完还原，所以失焦状态不会丢输入。

## 7. 后台截图

```powershell
.\SendRdpInput.exe --target 192.168.98.184:3389 --capture C:\rdpcap\shot.bmp
```

- 数据源是客户端的**主画面缓冲**（服务端推来的最新一帧），客户端最小化时仍在更新，所以后台可截。
- 输出 **32 位未压缩 BMP**（自顶向下）：3840×2160 约 33 MB。
- 尺寸由位图对象取（`GetObject`），分辨率与当前会话一致。

用 Python 转 PNG：

```python
from PIL import Image
Image.open(r"C:\rdpcap\shot.bmp").convert("RGB").save(r"C:\rdpcap\shot.png")
```

### 限制

- 截到的是**客户端缓冲**：远端锁屏/UAC 安全桌面不推流，会截到上一帧。
- 会话完全断开（注销）后画面停止更新，截到最后一帧。
- 不含鼠标指针（指针是独立通道合成到窗口上的）。

## 8. 空闲保活（F15）

连续 **60 秒无任何输入**就发送一次 `F15`（扫描码 0x66）。有输入立即重新计时；持续空闲则每 60 秒一次。

算作输入的只有真正送到远端的操作：本机键盘和鼠标，以及注入的 `--text` / `--key` / `--wheel` / 指针命令。
**`--capture` 截图、`--status`、`--keepalive` 查询都不算**，因为它们不向服务端发送任何输入。

> 2026-11-18 修正：旧版把所有成功的 WM_COPYDATA（包括截图）都当成输入，并且间隔是 2 分钟。
> rdp-reader 每秒截图时，F15 因此一次都没有发出（实测：每 30 秒截一次图、持续 150 秒，发出 0 次），
> 远端在最后一次真实操作后约 4 分钟内就锁屏了。

查询次数：

```powershell
.\SendRdpInput.exe --target 192.168.98.184:3389 --keepalive 1
```

## 12. 自动化接口：参数契约与实测（补充）

> 本节由 2026-11-16 实机逐项验证后补入，记录前文未覆盖的细节。

### 12.1 调用契约

`SendRdpInput.exe` 的解析逻辑是 `args.Length == 4`，**四个参数缺一不可**，
否则只打印 usage 并返回 `2`（`--status` / `--keepalive` 的第 4 个参数只是占位）：

| 命令 | 完整写法 | 备注 |
|---|---|---|
| 文本 | `--target HOST:PORT --text "…"` | 第 4 个参数即文本 |
| 组合键 | `--target HOST:PORT --key CTRL+A` | 用 `+` 连接，最多 4 个 |
| 状态 | `--target HOST:PORT --status query` | `query` 为占位 |
| 保活 | `--target HOST:PORT --keepalive 1` | `1` 为占位 |
| 截图 | `--target HOST:PORT --capture out.bmp` | |
| 滚轮 | `--target HOST:PORT --wheel -3` | 正数向上，负数向下 |

两条硬性前提（写在 `SendRdpInput.cs` 里，出错信息不明显，容易踩）：

1. **工具必须与 `wfreerdp.exe` 同目录**（或置于同目录的 `runtime\` 下）。
   放到别处会得到 `Expected exactly one matching client`，而不是“找不到程序”之类的提示。
2. 目标窗口按**标题等于主机名/IP（去掉端口部分）**匹配，且必须**唯一**。
   同一主机同时开两个客户端实例时匹配失败。

### 12.2 `--text` 的限制

- 长度 1–4096 个 UTF-16 码元。
- **不能含** `\0` `\r` `\n` `\t`，否则抛 `ArgumentException`。需要换行请另外发 `--key ENTER`。
- 底层是 Unicode 键盘事件（`freerdp_input_send_unicode_keyboard_event`），
  不经过键盘布局与输入法，中文、全角标点原样送达。

### 12.3 清空远端输入框

`--key BACKSPACE` 在部分编辑器（例如 OpenCode 的输入框）**不会**删掉已有内容。
可靠做法是先全选再删：

```powershell
.\SendRdpInput.exe --target $t --key CTRL+A
.\SendRdpInput.exe --target $t --key BACKSPACE
```

### 12.4 `InputSuspended` 的语义（实测纠正）

`--status query` 返回的 `InputSuspended=True` **不代表注入被拦截**。

实测：客户端最小化、`InputSuspended=True` 的状态下，`--text` 与 `--key` 仍然全部送达，
且本机前台窗口没有被抢走（回包 `ForegroundUnchanged=True`）。

该标志指的是**本地物理键鼠的捕捉被暂停**（避免后台自动化与用户在本地打字抢输入）。
客户端在每次注入前会把 `FreeRDP_SuspendInput` 临时置 `FALSE`、发完再还原
（`studio_input.h` 的 `studio_send_input()`），所以注入不受它影响。

### 12.5 实测耗时与体积

| 项目 | 数值 |
|---|---|
| `--capture` 单次耗时 | 1–2 s |
| 3840×2160 截图体积 | 31.6–33.2 MB（BMP） |
| 同上转 PNG 后 | 约 0.5 MB |
| `--text` 39 个中文字符送达 | < 1 s |
| 端到端（送提示词 → 远端模型回完） | 10–15 s 出结果，25 s 内画面稳定 |

## 14. 附：注入命令与 FreeRDP 底层 API 的对应

实现在 `client\Windows\studio_input.h` 的 `studio_send_input()`，逐条对应如下：

| kind | 命令 | 底层调用 | 备注 |
|---|---|---|---|
| `0x46524430` | `--status` | 读 `freerdp_is_active_state()` / `FreeRDP_UnicodeInput` / `FreeRDP_SuspendInput` | 返回 `1000 + 1(active) + 2(Unicode) + 4(Suspend)` |
| `0x46524431` | `--text` | `freerdp_input_send_unicode_keyboard_event()`：逐码元 `0` + `KBD_FLAGS_RELEASE` | 需 `FreeRDP_UnicodeInput`，否则返回 `2` |
| `0x46524432` | `--key` | `freerdp_input_send_keyboard_event()`（扫描码） | 先全量校验再发送，避免半截输入 |
| `0x46524433` | `--keepalive` | F15（扫描码 `0x66`），见 `wf_event.c` | 返回已发送次数 |
| `0x46524434` | `--wheel` | `freerdp_input_send_mouse_event()` + `PTR_FLAGS_WHEEL` | **单次最多 50 格**，超出部分静默丢弃 |
| `0x46524435` | `--capture` | `studio_capture_primary()` 导出主位图 | 载荷是 BMP 输出路径（UTF-8、NUL 结尾） |
| `0x46524436` | `--move` / `--click` / `--rclick` / `--down` / `--up` | `freerdp_input_send_mouse_event()`：`PTR_FLAGS_MOVE` / `BUTTON1` / `BUTTON2`（按下再 or `PTR_FLAGS_DOWN`） | 载荷 `int32 x` + `int32 y` + `uint32` 动作位（1/2/4/8/16） |

公共约束：

- 载荷 `cbData` 必须在 **1–8192 字节**之间。文本因此封顶 **4096 个 UTF-16 码元**，
  按键封顶 **2048 个事件**。
- 每次注入都会临时把 `FreeRDP_SuspendInput` 置 `FALSE`、结束再还原 ——
  这就是 `InputSuspended=True` 时仍能注入的原因（见 12.4）。
- `--text` / `--key` / `--wheel` / 指针类命令都要求连接处于 active 状态；断线时返回 `0`。
- 指针坐标是**远端会话像素**，左上角为原点（3840×2160 时任务栏约在 y≈2080）。
- 文本走 FreeRDP 官方 Unicode 键盘事件通道，与远端输入法/键盘布局无关；
  `--key` 走扫描码，所以只能用 `SendRdpInput.cs` 里 `Keys` 表列出的键。
